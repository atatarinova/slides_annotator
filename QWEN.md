# QWEN.md — Контекст проекта: Система автоматического аннотирования текста лекционных PDF-презентаций

## 1. Обзор проекта
Система предназначена для автоматического извлечения текстового контента, анализа и генерации структурированных аннотаций на основе текстового слоя и иерархии заголовков учебных презентаций в формате PDF.

### Основные задачи:
- Извлечение текстовых блоков, заголовков, подзаголовков, списков и текстовых таблиц из PDF-слайдов.
- Очистка извлеченного текста от колонтитулов, номеров слайдов и мусорных символов верстки.
- Восстановление логического порядка чтения текста на слайде и семантическая группировка слайдов в логические разделы.
- Генерация структурированной аннотации с помощью текстовых LLM.

*Примечание: Обработка растровых изображений, графиков, диаграмм и применение OCR не входят в задачи данного проекта.*

---

## 2. Технологический стек
- **Язык:** Python 3.11+
- **Парсинг текста из PDF:** PyMuPDF (`fitz` — извлечение текстовых блоков с метаданными шрифтов и координат `bbox`), `pdfplumber` (для структурированных текстовых таблиц).
- **Работа с AI / LLM:** OpenAI-совместимый API (текстовые модели серии Qwen, например `qwen-max` / `qwen-plus`), `instructor` или `langchain` (для Structured Outputs).
- **Валидация данных:** Pydantic v2.
- **Веб-интерфейс / API (если применимо):** FastAPI, Streamlit / Gradio.
- **Тестирование и качество кода:** `pytest`, `ruff`, `mypy`.

```text
├── src/
```

## 4. Стандарты разработки и стиль кода
1. **Типизация:** Обязательна строгая аннотация типов (`typing`, `list[str]`, `dict[str, Any]`) во всех функциях и методах.
2. **Валидация:** Все входные и выходные структуры данных (модель слайда, секции и итоговой аннотации) описывать через `BaseModel` из Pydantic.
3. **Асинхронность:** Сетевые запросы к LLM API выполнять асинхронно (`asyncio`, `AsyncOpenAI`) с ограничением конкурентности (`asyncio.Semaphore`) и механизмом ретраев (`tenacity`).
4. **Промпты:** Запрещено зашивать длинные системные промпты внутрь `.py` файлов. Выносить их в директорию `prompts/`.
5. **Обработка ошибок:** Не использовать голый `except:`. Применять кастомные исключения (`EmptyTextLayerError`, `PDFParsingError`, `LLMGenerationError`).

## 5. Специфика предметной области и эвристики парсинга

### 5.1. Эвристики определения и обработки заголовков
При извлечении текста через PyMuPDF (`page.get_text("dict")`) использовать следующие правила:
1. **Ранжирование по размеру шрифта и начертанию:** Вычислять медианный размер шрифта основного текста (`body_font_size`) по всей презентации. Блоки со шрифтом больше медианного (например, `>= 1.2 * body_font_size`) или выделенные полужирным (`bold`) считать кандидатами в заголовки.
2. **Позиционный приоритет (`bbox`):** Заголовок слайда (`slide_title`) с высокой вероятностью находится в верхней трети страницы (`y0 < 0.3 * page_height`). Если вверху несколько блоков, выбирать блок с наибольшим размером шрифта.
3. **Титульный слайд и разделители секций (Section Headers):** Если на слайде присутствует только 1–2 текстовых блока с крупным шрифтом по центру экрана и отсутствует основной текст списков, помечать такой слайд как **разделитель крупного раздела** (`is_section_divider = True`).
4. **Слайды-продолжения (дублирующиеся заголовки):** Если заголовок текущего слайда совпадает с предыдущим или содержит пометки вроде `(продолжение)`, `(cont.)`, `2/3`, объединять текстовый контент этих слайдов в единый логический фрагмент.
5. **Слайды без явного заголовка:** Если на слайде не найден блок, подходящий под критерии заголовка, наследовать заголовок предыдущего слайда с пометкой `[Без заголовка / продолжение]` и передавать в LLM для смысловой привязки.
6. **Многоколоночная верстка:** Сортировать текстовые блоки сначала сверху вниз (с допуском по `y` в пределах высоты строки), затем слева направо, чтобы не смешивать текст из двух колонок в одну строку.

### 5.2. Общие правила обработки текста
- **Проверка на пустой текстовый слой:** Если в PDF отсутствует извлекаемый текст (например, документ состоит только из сканов), парсер должен явно выбрасывать исключение `EmptyTextLayerError`.
- **Фильтрация шума (колонтитулов):** Находить текстовые блоки с идентичными координатами (`bbox`) и повторяющимся текстом (или регулярным паттерном номеров страниц `^\d+$` / `Слайд \d+`), которые встречаются более чем на 40% слайдов, и удалять их до отправки в LLM.
- **Борьба с галлюцинациями:** Промпты должны строго требовать опоры *только* на извлеченный текст и заголовки презентации без додумывания внешней информации.
- **Работа с длинными лекциями:** При объеме 50+ слайдов группировать слайды по выделенным разделам и выполнять суммаризацию поэтапно (по каждому разделу отдельно) во избежание потери деталей в длинном контексте.

## 6. Желаемая структура итоговой аннотации
Результат работы системы (как на уровне Pydantic-модели для JSON/API, так и при экспорте в Markdown/DOCX) должен строго соответствовать следующей иерархической структуре:

1. **Основная тема презентации (`main_topic`):**
   - Краткая и точная формулировка главной темы всей лекции (1–2 предложения), сформированная на основе титульного слайда и сквозного анализа заголовков.
2. **Основные разделы (`sections`):**
   - Логически сгруппированный список ключевых тематических блоков лекции, сформированный на основе заголовков разделов и кластеризации слайдов.
   - Для каждого элемента списка указывается **название раздела (`section_title`)** (и опционально диапазон слайдов, например, *Слайды 3–8*).
3. **Текстовая аннотация по каждому разделу (`section_summary`):**
   - Внутри каждого раздела содержится связный, структурированный текстовый абзац (или несколько абзацев), раскрывающий суть данного раздела: основные тезисы, определения, выводы и логику изложения лектора строго по тексту слайдов этого раздела.

### Пример ожидаемого формата (Markdown-представление):
```markdown
# Основная тема: [Название и главная идея лекции]

## 1. [Название первого раздела]
[Связная текстовая аннотация первого раздела, обобщающая ключевые тезисы и факты со слайдов этого блока.]

## 2. [Название второго раздела]
[Связная текстовая аннотация второго раздела...]
```
