# Обзор конвейера аннотации

Весь процесс создания структурированной аннотации лекционных PDF‑презентаций реализован как цепочка из модулей, расположенных в пакете **src**.  Ниже приведено краткое описание основных этапов:

1. **Извлечение исходного текста** – модуль `src.parsers` использует PyMuPDF (`fitz`) и pdfplumber для чтения текста, шрифтов и координат блоков со страниц PDF.  Результат – список объектов `PageTextBlock` с полями `text`, `bbox`, `font`, `size` и `flags`.

2. **Наложение эвристик** – `src.processors` применяет правила, описанные в разделе *5.1. Эвристики определения и обработки заголовков* из `QWEN.md`.  На этом этапе:
   * определяется заголовок каждого слайда;  
   * устраняется колонтитулы, нумерация страниц и мусор;  
   * сгруппированы слайды в логические разделы (`Section`), задавая диапазоны слайдов.

3. **Генерация запросов к LLM** – слой `src.llm` формирует промпты из файлов в каталоге `prompts/`, загружает их через `Instructor` / `OpenAI`‑совместимый клиент, а полученный ответ парсится в схему Pydantic‑модели, описывающие финальную аннотацию (`MainTopic`, `Section`, `Annotation`).  Если ключ LLM не задан, модуль падает с `LLMConfigurationError` и ожидается подмена кода stub‑клиентом.

4. **Экспорт** – `src.exporters` превращает полученную структуру в требуемые форматы:
   * Markdown (`md_exporter.py`);
   * JSON (`json_exporter.py`);
   * DOCX (`docx_exporter.py`);
   * TXT (`txt_exporter.py`).

5. **Интерфейс API** – если включён модуль `src.api`, то FastAPI‑сервер предоставляет эндпоинты для загрузки PDF‑файла, получения промежуточных результатов и финальной аннотации.

6. **Проверка и тестирование** – весь поток контролируется `pytest`, `ruff`, `mypy`.  Тесты упакованы в `tests/` и проверяют шаги от парсинга до экспорта.

> ⚠️  В текущем окружении нет ключа LLM, поэтому этап генерации аннотаций не выполняется автоматически.  Для проверки до и после LLM‑шага можно заменить клиент на заглушку, которая возвращает валидный экземпляр модели.
